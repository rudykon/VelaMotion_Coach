# openvela 手表快应用验收

在包含 `package.json`、`src/manifest.json` 和 `scripts/` 的快应用目录执行。先读应用 README，识别包名、RPK 路径、模拟器版本及真实数据能力；其他项目需据实调整命令。

## 固定证据来源

- 先运行核心测试与运动场景测试，再执行 `npm run release`。保留正式包；测试成功不代表已在设备运行。
- 部署前计算 RPK 内页面 bundle 的 SHA-256；部署后读取设备对应文件比对。NuttX shell 可能在命令失败时返回 0，必须检查错误文本、文件内容和安装后状态。
- Vela5 可用 `pm install` / `am start`；部分 arm64 镜像只有 ADB 文件推送，需要解包推送后在串口执行 `vapp hap://app/<包名>`。按实际镜像选择，不反复尝试同一不支持命令。

## 验证用户可见行为

- 正式源码关闭自动开始、自动翻页。通过真实点击开始训练、确认动态变化、停止，再切换页面。
- 运动状态同时用日志和活动卡画面确认。不要把强度条的相同颜色误当作活动文字；裁切判断区域应只覆盖目标组件。
- 为每页核对当前 QA 标记与页面内容，检查空白、表盘误截、边缘遮挡和截图重复。界面换配色时同时更新采集器与提交检查器的标记表。
- 页面卡住时先确认应用是否在前台、旧进程是否退出、安装文件是否更新；限制重试次数。失败后保留错误报告，不能关闭严格 QA 以伪造通过。

## 分开证明传感器能力

- 官方 gRPC Mock 的 set/get 成功只证明模拟器注入和回读；应用内 Mock 识别应单独验证。除非核实完整消费链，不能写成应用已消费全部官方 Mock 数据。
- 真机缺失 GYRO 时，六轴分类应在启动前阻断；不能填零伪造陀螺仪。心率接口失败、手机未连接也应如实显示。
- 合成场景测试用于逻辑回归；概率/置信度不能写成真人识别准确率。

## 整理交付物

本项目执行 `npm run demo:capture`、`npm run submit:prepare`、`npm run submit:check`。截图合成的视频标明为界面演示，不声称连续操作录屏。检查 ZIP 中源码、RPK、文档、截图均与当前文件一致，排除签名私钥、依赖、原始训练数据和缓存。

遵守作者的日志公开范围。本次作者要求不公开开发日志，ZIP 必须排除 logs/、JSONL 和日志摘要；如未来获得补交授权，再按官方规范处理，并独立核验其格式与来源。

最终报告列明本轮通过项、未验证项、源码与 RPK 哈希及证据文件。远程提交是否完成以实际 PR/合入状态为准。此 Skill 不授予发布、签署协议或修改其他仓库的权限。
