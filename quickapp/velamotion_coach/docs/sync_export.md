# F8 手机同步 / 摘要导出说明

## 当前实现

应用第四页“同步复盘”内置“手机同步”面板：

- 动态加载并检测 `@system.interconnect` 连接状态，能力不可用时不阻断应用。
- 将最近一次训练摘要通过 `interconnect.send()` 发送到手机端。
- 无手机端或互联不可用时，页面展示同一份 JSON 摘要，便于调试和提交说明。

发送 payload 类型：

```json
{
  "type": "velamotion.session.summary",
  "version": 1,
  "totalSec": 0,
  "activeSec": 0,
  "segmentCount": 0,
  "riskCount": 0,
  "activityShares": [],
  "risks": []
}
```

## 边界

- 当前只发送摘要，不发送原始 ACC/GYRO/HR 波形。
- 如果未安装配套手机端应用，`diagnosis` 可能返回未连接或对端未安装。
- 该能力是 F8 进阶项，不影响手表端独立运行。

## 处理状态契约

- 训练运行中只显示“腕上初筛”。
- 有效停止并保存后显示“待同步”。
- 摘要发送成功只进入“已发手机 / 等待精确结果”，不能伪装成手机精确复盘。
- 只有收到 `type = velamotion.session.precise_result`、`version = 1`、`completeScaleSet = true` 且 `scalesUsed` 同时包含 3s、5s、8s 的入站结果，才进入“手机精确复盘”。
- 手机返回降级模型或尺度不完整时继续保持待同步，并明确提示未作为精确结果采用。
- 在尚未引入关联码的当前协议中，入站结果只在“摘要发送成功”后的等待窗口且本地确有待同步记录时接收；运行中、未发送、普通待同步和已完成状态下的主动/重复回包都会拒绝。
- 该窗口门禁仍无法区分“更早一次请求的迟到回包”和当前请求。跨请求精确关联必须等用户授权后再增加会话关联标识；当前材料不声称已经解决这项边界。
